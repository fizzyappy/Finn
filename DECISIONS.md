# Decisions

Every non-obvious choice, why it was made, and what it cost. Rows are in the order they were made
(setup → data → push engine → pull engine → app → deployment), so later rows sometimes refine earlier ones.

The decisions that shaped FINN most: primary sources only, with no bot-protection workarounds; the model reads
and Python decides (no LLM arithmetic, no LLM verdicts where a number exists); a wrong number is worse than no
number ("not verified" cards); quotes must be found word for word or are dropped; the alert default came from a
backtest, not a guess; the app ships a snapshot so the link always works, with a live backend for new companies.

| Decision | Why | What we gave up |
|----------|-----|-----------------|
| Project lives in a local folder, not OneDrive | OneDrive sync fights with `node_modules`, `.venv` and SQLite files | Automatic cloud backup; GitHub is the backup instead |
| Earlier code kept in `_old\` (git-ignored), rewritten in `backend/finn` | Old code was well designed but never ran against live sources (its own notes say so) and was written for a different LLM provider | Some old features (classifier, push digest, research engine) not ported yet; they come back in Tasks 3–4 |
| Cache stores JSON in SQLite, never pickle | Readable, safe to load, survives pandas upgrades | Slightly more code to turn data into tables |
| Cache raw pages, parse on every read | A parser fix applies at once instead of after the cache expires (we hit this bug live) | A few ms of parsing per read |
| Never work around bot protection. A 401/403 marks the host blocked for 30 min | Respect the sites' wishes; the safety check on this PC also refused browser-fingerprint tricks | BSE and NSE announcement APIs are unusable from this PC (both return 403) |
| Filings come from 4 sources merged: BSE API, NSE API, screener recent list, RSS store | No single free source is complete. Each answer reports which sources worked | Full 7-day history is not guaranteed until the RSS poller has run for a while |
| Poll BSE + NSE official RSS every 5 minutes into SQLite | RSS feeds are published for programs to read, and they work from this PC | The feeds hold only the newest ~25 items, so very busy periods can be missed between polls |
| Company list from NSE's own `EQUITY_L.csv`; BSE code from screener | Primary source, covers every NSE company, gives ISIN | BSE-only companies resolve only by their 6-digit code |
| Match a quarter to the year-ago quarter by period-end date | Counting columns breaks when a column is missing | None |
| Growth % is withheld (with a reason) when the base is zero or negative | "+250% profit" from a loss misleads investors | Some cells show a note instead of a number |
| Banks/NBFCs detected from row labels (Financing Profit, NPA), not a list of names | Works for every lender, no company-specific code | None |
| Prices: yfinance first, Yahoo chart JSON as fallback; late daily bar filled from Yahoo's quote and marked provisional | yfinance is what the challenge suggests; the fallback survives yfinance breakages; we saw the late-bar quirk live | Provisional bars have no opening price |
| Results document = the results filing if found, else the investor presentation filed after the quarter ended | screener's own results PDFs require a screener login; we do not create accounts | Some companies (e.g. INFY this quarter) have no reachable results PDF from this PC |
| PDFs only from exchange sites, or company-site PDFs that the company's own document list links to | Primary sources only; stops the API being used to fetch arbitrary URLs | PDFs elsewhere on the web are refused |
| Keep extracted PDF text exactly as extracted; normalise only for searching | Quotes must match the source word for word | Raw text has PDF line breaks |
| Gemini models: `gemini-3.5-flash-lite` (fast, bulk), `gemini-3.5-flash` (harder tasks), behind one router (Task 3) | Tested live with this key: both answer. `gemini-2.5-*` is closed to new keys; `gemini-3.8-flash` timed out | Newest models not used until they respond reliably |
| BSE announcements API dropped for good; filings = RSS store + screener recent list | One retry with standard Referer/Origin headers was blocked by this PC's safety check as bot-check circumvention; the decision is to respect that and not pursue it | Full per-company filing history before the RSS poller started |
| Default alert = "notable move": 3 sigma after the market AND volume >= 2.5x its 20-day average | 90-day backtest: "2.5 sigma" alone fired 58 times (~3/week) across 18 stocks, too noisy for a push; the combined rule fired 21 times (~1.2/week) | Some single-factor moves (big move on normal volume) no longer push by default; still available as presets |
| Push engine reuses the old taxonomy idea (ordered rules, sub-types, base scores) but rewrites the rules against 90 real filings | The old rules missed real subject formats (e.g. "Con. Call Updates" is a meeting, not a results call) | Rules are in-sample on the labelled set; accuracy is reported with that caveat |
| Rules first; Gemini Flash-Lite only for filings no rule recognises (reading page 1 of the PDF) | Held-out set: rules alone 53% → rules + Gemini 82% on first pass, for 15 calls; most filings never reach the model | A little latency on unknown filings |
| Materiality = base x modifiers x holding weight x preference + market-reaction bonus, with every factor returned | The app can answer "why am I seeing this?"; thresholds hero ≥ 0.6, one-liner ≥ 0.3 | Weights are hand-set, not learned |
| Results numbers: model reads only the results-table pages (mini PDF); Python checks 3 periods, PBT − tax = PAT, totals, units, and matches screener before "verified" | A wrong number is worse than none. The check caught real issues live: ITC gross revenue incl. excise (fixed by netting excise), half-yearly SME reporters, columns printed out of order | Slower first read (~3–50 s per filing, then cached) |
| Scanned filings (no text layer) under 25 pages go whole to the model | Gemini reads page images; Happiest Minds' and Team24's scanned results verified this way | More tokens for those filings |
| Headline of a verified results card is written by Python from the card's numbers | Live run showed an LLM summary quoting standalone PAT while the card showed consolidated | Less varied wording |
| Summaries: every number must appear in the filing, praise words need an amount, action words (upgrade, acquire…) must be the filing's; fixed formats (credit rating, dividend) use templates | Live run caught "ICRA upgrades" when the rating line said "A+ reaffirmed; outlook revised to Positive" | Some summaries fall back to the cleaned subject line |
| People card quotes must be found word for word in the filing (page recorded), else dropped | SEBI requires a brief profile in the filing itself; no LinkedIn scraping | Thin profiles when a company files little |
| Screener's "detail" lines are used only to help classify, never shown | They are screener's own summaries, not the filing | – |
| Alerts measure a day against the stock's own normal (move after Nifty x beta, in sigmas) and volume vs 20-day average; a backtest shows how often a rule fires | A 3% day is noise for a small cap and big for a utility; the 90-day backtest showed 2.5-sigma moves fire ~3x more often than a bell curve predicts | – |
| Filings before a price move are shown as "filed before", never "caused" | Timing is a fact; cause is not | – |
| Escalation tier (`gemini-3.5-flash`) often times out (4 of 10 calls today); router falls back and labels it | Keeps the pipeline moving on the free tier | Second attempts are sometimes answered by Flash-Lite |
| Pull engine: table sections (snapshot, trajectory, balance sheet, cash quality) use no LLM and are published first | Fast, free, auditable; the app shows something within seconds of a cold start | Business description beyond segments is not written |
| Transcript speakers found from the document itself (recurring "Name:" or name-only lines; running headers taken only from page edges); roles from moderator introductions, then the participant list, then question/answer behaviour | Every company formats transcripts differently; a frequent speaker was first mistaken for a page header (Infosys CEO) and a CFO for an analyst (HDFC Bank) until these rules | Unusual layouts can still mislabel a speaker |
| Quote checks ignore all whitespace (PDF text breaks words: "gui dance"), but every other character must match; quotes over a page break are found | A strict whitespace match rejected true quotes | – |
| Promise verdicts decided by Python from the tables; the reason line is also written by Python from the numbers | The number decides; no model judgement needed where a number exists (rules before LLM) | Non-numeric promises are tracked but marked "Not measurable" |
| Promises carry a scope (company vs a named segment); only company-wide targets are measured against company-wide tables | Live run: L&T's 8.5% margin guidance is for its core E&C business; comparing it with group margin wrongly said "Kept" | Segment-level promises are "Not measurable" |
| Constant-currency / USD guidance (IT services) marked "Not measurable" | Statements report INR; converting would invent a number | Infosys's revenue guidance cannot get a verdict |
| "Quietly dropped" needs two later calls (before the deadline) with no word on that metric at all | It is a strong charge; one quiet call is "not repeated yet"; a metric discussed for another period is not "dropped" | Slower to flag a real drop |
| Narrative vs numbers is deterministic: present-tense upbeat words on a metric in the latest call vs that metric falling YoY | No model opinion; forecasts and hedged sentences are excluded | Misses subtler divergences |
| Bull/bear: Flash-Lite phrases bullets from a numbered fact pool; Python keeps only bullets citing real facts with matching numbers | Every bullet stands on a number | Bullets are plain |
| Research cached by (ticker, newest source document date); one job at a time | Re-reading only when a company files something new; protects the free quota | Concurrent requests queue |
| Research companies: TITAN replaces TRENT | screener lists no concall transcripts for TRENT | – |
| App ships a frozen snapshot of real outputs (briefs for every window, research for 21 companies, 120 days of alert measures, NSE company list); live backend used when reachable | The submitted link must always work, even if a free backend is asleep or a source refuses | Snapshot ages until re-exported |
| Alerts backtest runs in the browser on the exported per-day measures | The slider updates instantly with no server | Limited to the last 120 trading days |
| Hand-written CSS + Framer Motion; no UI kit; hash routing; own service worker | Small bundle (~100 KB gzip), full control of the look, works as static files on any host | More CSS to maintain |
| Verification with playwright-core on the installed Chrome (no browser download), axe for accessibility, a horizontal-overflow check | Catches regressions on every screen and state; found and fixed an overflowing chip and low-contrast text | Not a full Lighthouse run |
| HTTP retries ignore a site's Retry-After (short backoff instead) | An export once took 97 minutes, most likely waiting on a "retry after" reply; the stale cache covers refusals | Slightly more retries against a busy site |
| Long PDFs (> 60 pages) skip the slow fallback text reader; reading an annual report has a 4-minute budget | One annual report took over 10 minutes | Scanned annual reports yield no segment data |
| Render backend is required for the deployed app (VITE_API_BASE); snapshot stays the fallback | ENAM may test a company we did not pick | Render free plan sleeps: up to ~50 s wake-up, shown to the user; keep-warm ping every 10 min |
| A committed seed (~300 KB) of cached model answers and finished research, loaded by fresh servers | Render's disk is temporary and GitHub Actions starts empty; without it every restart would re-pay | Seed must be refreshed (the daily job does it) |
| Daily GitHub Action rebuilds the snapshot and commits it; Vercel redeploys on the push | Fresh filings without the PC; only new filings cost Gemini calls (seed + cached database) | A run that fails for most holdings keeps the previous data rather than replacing it |
| Dodged judge: model flags only clear non-answers; Python keeps "dodged" only with evidence in the quoted answer | First pass flagged a clarification request as a dodge; prefer fewer, correct flags | Some real evasions are labelled "partly" (3 of 15 hand-checked labels err that way) |
| Custom window is a real date range; filtered on the device inside the 14-day snapshot, older ranges from the live backend | Instant inside the snapshot, no server needed | Ranges older than 14 days need the backend |
| Results cards try up to 3 exchange-filed documents (own filing, folded-in filings, same company's results filings, RSS) | One unreachable PDF should not cost the card | More model calls when the first document fails |
